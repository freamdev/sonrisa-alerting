# Application boundary and intended contracts

This folder defines application contracts and access policies without concrete database, REST, Email or Slack dependencies. Phase 02 adds `ISelectionService` for reading and independently updating topic/channel choices, implemented by Infrastructure. Internal callers supply a user ID; Phase 07 HTTP endpoints derive it from the authenticated principal and enforce authorization/CSRF. `SelectionUnavailableException` rejects new choices of globally disabled items without rewriting existing preferences. See `docs/phase07-api.md` for management contracts and validation.

- `INewsSource.ReadAsync`: asynchronously obtain validated, normalized `AlertEvent` values from the approved mock REST contract, honor cancellation and expose source failures separately from delivery failures. Infrastructure owns HTTP payload parsing and topic-code normalization; senders never consume source JSON.
- `IChannelSender`: identify the supported channel and send a normalized alert to an agreed recipient destination, honoring cancellation and reporting success or failure. Phase 05 uses Identity email and server-owned per-user Slack channel webhooks. Sending once does not own retries. `ChannelDeliveryException` carries only enum-selected safe error codes, without provider exceptions.
- Alert routing service: accept a normalized alert, ignore known external IDs, match enabled users and independently selected topics/channels, and record deliveries and outcomes. Own the maximum of three total attempts per delivery in Phase 04; senders do not multiply attempts.

Phase 04 defines `IAlertDispatcher` for validated internal `AlertEvent` ingestion and explicit pending recovery, plus `IChannelSender`/`DeliveryMessage` for one send attempt without retry ownership. Messages carry normalized content and internal recipient identity. Infrastructure implements persistent routing, Phase 05 destination resolution/adapters and startup recovery. Recording fake senders remain test-only. See `docs/phase04-routing.md` for the approved exponential retry policy, `docs/phase05-channels.md` for adapters, and `docs/phase06-source-worker.md` for source mapping and sequential polling.
